<objective>
Onglet "Mes photos" du bénévole : charger des photos, les partager avec la communauté Hub (fil + profil Hub), et les proposer à la galerie publique (brouillon, modération admin existante).

Decisions (from 261010-n27-CONTEXT.md, numbered here for traceability):
- D-01: Communauté = Hub (worker/hub.ts, D1 + R2, client/src/features/hub). Shared photos visible on the volunteer's Hub profile AND in the Hub feed.
- D-02: Galerie publique = proposition + existing admin moderation (gallery_photos status 'draft' -> admin publishes). No direct publication.
- D-03: The current "Galerie" tab of client/src/features/volunteer/pages/VolunteerProfile.tsx (L279-282, L731-746) is REPLACED by "Mes photos".

Identity (verified by planner): VolunteerProfile runs on the Supabase site session; the Hub uses its own magic-link token. hub_members.email is the normalized (trim+lowercase) t_volunteers email (worker/hub-d1.ts upsertMember / isEligible). The Supabase user resolved by createWorkerContext carries `email`. So the bridge is: site Bearer -> deps.adminUser resolver -> email -> isEligible -> upsertMember -> same hub_members row the magic link would open. No second login for the volunteer.

Data model (Claude's discretion, minimal): a "photo" = an entry of hub_post_media on one of the member's visible hub_posts (so photos posted from the Hub composer also count). Uploading from "Mes photos" = creating a Hub post (caption optional, default "Nouvelles photos"). One new table only: hub_gallery_proposals (one proposal per R2 path). No new dependency.

Purpose: volunteers share event photos in one place; the public gallery gets moderated contributions.
Output: worker routes + D1 table + tests, Mes photos tab, Hub profile photo grid + member profile view.
