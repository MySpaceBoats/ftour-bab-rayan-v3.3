# Quick 261010-n27: "Mes photos" tab for volunteers Summary

A confirmed volunteer signed in with the site (Supabase) session can upload up to 4 photos from the "Mes photos" tab. The photos are shared to the Hub as a post (feed and profile) and can be proposed to the public gallery as a moderated draft.

## What was built

- **Identity bridge (worker/hub.ts `volunteer()`)**: site Bearer token -> `createWorkerContext` user -> email trimmed and lowercased -> `isEligible` (confirmed/present) -> `upsertMember` -> the same `hub_members` row the magic link opens. Demo user, missing email, ineligible email and suspended member are all refused. No second login.
- **Routes**: `POST volunteer/media`, `POST volunteer/posts` (same handlers and rate limits as the Hub ones via `who()`), `GET volunteer/photos`, `POST volunteer/photos/propose`, `GET members/:id` (hub token).
- **Gallery proposal (D-02)**: new idempotent table `hub_gallery_proposals` (PK `r2_key`). `proposeToGallery` claims the photo, then an injected `publish` copies the private hub R2 object to `gallery/original/<uuid>.<ext>` and inserts a `gallery_photos` row with status `draft`, `validation_token` NULL, `uploaded_by` = email. If the copy or insert fails, the claim is released and the copied key is removed.
- **Photo status**: `memberPhotos` returns `gallery_status` (null, draft, published, rejected; a gallery row deleted by an admin shows as rejected).
- **Client**: `MyPhotosPanel` (upload and share, optional "propose to the gallery" checkbox, per-photo propose button and status badge, link to the Hub feed). `HubProfilePage` shows a photo grid and a read-only member view at `/:lang/benevole/espace/membre/:id`. `PostCard` author links to that profile. The route is registered before `/espace`.

## Known limitation: production visibility risk (pre-existing, not fixed)

`volunteerProfile.*` tRPC procedures exist only in `server/routers.ts` (12 references) and not in `worker/routers.ts` (0). `/profil-benevole` loads its profile through `trpc.volunteerProfile.me`. If the production client talks to the Cloudflare Worker, the page shows "Impossible de charger le profil." and no tabs render, which also hides the new "Mes photos" tab. The new `/hub/volunteer/*` routes live in the Worker and work independently, but the tab is only reachable if the profile page itself loads. A follow-up should port `volunteerProfile.*` to the Worker or surface the Mes photos panel outside that gated page.
