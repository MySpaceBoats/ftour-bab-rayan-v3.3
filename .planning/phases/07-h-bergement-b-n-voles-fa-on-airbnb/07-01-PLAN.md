# Phase 7 — Plan 01 : module Hébergement bénévoles (façon Airbnb)

## Objectif

Ajouter dans l'espace bénévole un module d'hébergement entre bénévoles : annonces de logement,
recherche/filtres, fiche, demandes de séjour (avec anti-chevauchement), espace hôte, messagerie
dans la demande, avis, et modération admin — sur le même socle que le hub et la marketplace
(D1 `hub_members`/`hub_sessions`, media R2 bucket logique `hub`, REST `/hub/stay/*`).

## Décisions

- **Worker uniquement** : comme le hub et la marketplace, le module n'existe pas côté serveur Node
  (pas de tRPC) ; tout passe par le Worker Cloudflare (D1 + R2).
- **Aucun paiement** : le prix est informatif (gratuit / participation / prix par nuit en MAD),
  comme la marketplace. Pas de flux d'argent dans ce module.
- **Anti-chevauchement strict** : une demande `pending` bloque déjà les dates. Deux demandes ne
  peuvent donc jamais couvrir les mêmes dates ; accepter une demande n'a pas à refuser les autres.
- **Avis voyageur → hôte** : un avis par demande, possible dès que l'hôte a accepté la demande.
- **Messagerie par demande** (pas de fil global) : `st_request_messages`, fermée dès que la demande
  est refusée ou annulée.
- **Pas de seed démo dans ce plan** : les données de démo du hub (`scripts/hub-demo`) restent
  inchangées ; à étendre dans un plan 07-02 si voulu.

## Tâches

1. **Schéma D1** — `worker/d1/stay.sql` : 6 tables + index, CHECK de validation (longueurs, enums,
   format de date `YYYY-MM-DD`, `end_date > start_date`, `guest_id <> host_id`).
2. **Data layer** — `worker/stay-d1.ts` : validation (`cleanListing`), recherche paginée
   (kind/ville/texte/prix/voyageurs/dates/mine), fenêtre de dispo, création/decision de demande,
   messagerie, avis, signalements/modération admin. Temps injecté (`nowMs`).
3. **Routes REST** — `worker/stay.ts` (`handleStayRoute`) + montage `stay/` dans `worker/hub.ts`.
4. **Tests hermétiques** — `worker/stay-d1.test.ts` (domaine) et `worker/stay.test.ts` (REST, auth,
   admin) avec un faux D1 sur `node:sqlite`.
5. **Client** — `stay-api.ts`, `format.ts`, 5 pages (liste, fiche, formulaire, demandes, demande),
   routes `App.tsx`, entrée de navigation `Hébergement` dans `HubShell` (+ 5 onglets mobiles, badge).
6. **Admin** — `StayAdmin.tsx` (signalements + logements) branché dans `AdminHub.tsx`.
7. **Vérifs** — `pnpm check` (aucune nouvelle erreur), `pnpm test` (suite verte, nouveaux tests
   compris), `pnpm build:worker` (bundle worker OK).
