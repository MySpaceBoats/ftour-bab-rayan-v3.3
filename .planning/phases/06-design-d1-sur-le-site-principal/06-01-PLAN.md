## Palette decision (Claude's discretion per 06-CONTEXT — listed deviation)

The locked decision is "palette = d1 exactly (hue-wise)". The literal d1 hexes are much lighter than olive (d1 base relative luminance 0.165 vs olive 0.100), which fails AA in 4 token pairs and regresses ~600 hardcoded colour pairings (e.g. cream/90 text on base 5.03 -> 4.48, khaki #C9B97A labels on dark cards 4.76 -> 4.37, tan restaurant CTAs 3.15 -> 2.78).

**Chosen rule: luminance-matched hue swap.** Every legacy olive hex is replaced by a colour that has the exact d1 hue + HSL saturation of its slot and the same WCAG relative luminance as the olive it replaces (rounded so it is never lighter). WCAG contrast depends only on relative luminance, so every existing pairing — token pairs, the ~600 hardcoded Tailwind/inline pairs, alpha text such as `text-[#F2E9D3]/70`, email HTML — keeps its current contrast ratio within 1%, without auditing each pair. Hue drift vs d1 is at most 1.6 degrees. Visible consequence: the site is the d1 mauve, one value step deeper than the d1 preview (base L 0.40 vs 0.51 in HSL).

Rejected: (a) literal d1 hexes — 4 AA failures in token pairs (cream on base 4.00, cream on soft 2.90, creamSoft on soft 2.57, admin primary 4.28); (b) "minimal nudge" (base #914C5B, dark #733B48, soft #A35063) — fixes the token pairs but still regresses alpha text and khaki/tan accent pairs listed above.

## Gate specification (scripts/palette-d1.mjs, default mode)

- Check 1 — mapping parity, per PALETTE row (13 rows): relativeLuminance(shipped) <= relativeLuminance(legacy); contrast(legacy, shipped) <= 1.01; circular hue distance between shipped and the d1 reference of its slot <= 3 degrees.
- Check 2 — index.css slot values: `:root` `--bg-olive`, `--bg-olive-dark`, `--bg-olive-soft`, `--chart-5` and admin-v2 `--olive`, `--olive-deep` equal the shipped hex of rows 1, 2, 3, 5, 1, 4 respectively (case-insensitive).
- Check 3 — token pairs, for each theme `:root`, light (`.light, [data-theme="light"]`, falls back to `:root`), admin-v2 (`[data-theme="admin-v2"]` first block, falls back to `:root`): foreground/background, card-foreground/card, popover-foreground/popover, primary-foreground/primary, secondary-foreground/secondary, muted-foreground/muted, muted-foreground/background, muted-foreground/card, accent-foreground/accent, sidebar-foreground/sidebar, sidebar-primary-foreground/sidebar-primary, sidebar-accent-foreground/sidebar-accent: minimum 4.5 (WCAG 1.4.3 AA) — except these pre-existing olive sub-AA pairs whose minimum is their olive baseline: `:root` muted-foreground/muted 3.95, `:root` accent-foreground/accent 4.46, `:root` and light sidebar-accent-foreground/sidebar-accent 4.46, light muted-foreground/muted 3.95, light muted-foreground/background 4.46. Plus ring/background minimum 3.0 (WCAG 1.4.11 non-text) in every theme. destructive/* is excluded (not a palette token, unchanged).
- Expected shipped ratios (for the summary): `:root` fg/bg 5.76, muted-fg/muted 3.96, accent 4.47, ring 3.67; light primary 5.76, muted-fg/bg 4.47; admin-v2 primary 6.15, accent 9.42.
- Output: one line per check starting with `PASS ` or `FAIL ` — Check 1 one line per PALETTE row (all three conditions, 13 lines), Check 2 one line per slot token (6 lines), Check 3 one line per theme x pair (3 x 13 = 39 lines), 58 lines total — then `palette-d1: 58 checks, <k> failed`; `process.exitCode = 1` when k > 0.
